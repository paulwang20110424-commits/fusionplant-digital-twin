# FusionPlant Digital Twin

**Interactive simulated fusion-plant digital twin and real-time control console.**

> ⚠️ **SIMULATION ONLY.** Every number in this application is generated by a local,
> simplified 0-D physics model. Nothing is measured, nothing is commanded, and
> nothing is connected to a real fusion device. The model is an educational and
> software-validation artefact — it cannot predict the behaviour of any real
> tokamak and must never be used for engineering, safety or operating decisions.

A single-page industrial console that runs entirely in the browser: a live
simulation engine, a procedural 3D tokamak, dense multi-channel telemetry,
fault injection, scenario comparison, and local data recording/export.

## 2. What you can actually do

### Console shell
- 9 pages: **OVERVIEW · REACTOR · MAGNETIC FIELD · HEATING · COOLING · POWER GRID ·
  DIAGNOSTICS · SIMULATION · HISTORY**
- Top status bar: run state, plant phase, simulated clock, time scale, scenario,
  online devices, active alarms, `SIMULATION MODE` badge, full-screen toggle.
- Transport controls: **START/PAUSE · RESET · E-STOP (latching SCRAM)**.
- A single `requestAnimationFrame` loop drives the engine; hidden tabs pause cleanly
  and resume without a catch-up spike.

### 3D tokamak (overview + reactor pages)
- Procedural ITER-like assembly: transparent vacuum vessel, 18 D-shaped TF coils,
  7 PF rings, central solenoid, divertor, cryostat envelope, 8 support legs,
  schematic helical field lines, and the glowing plasma torus.
- Orbit / zoom / pan (damped), auto-orbit, camera reset.
- Click any component (or label sprite, or the component list) to inspect it.
- View modes **FULL / CUTAWAY / PLASMA**, plus per-structure visibility toggles
  (plasma, vessel, TF, PF, solenoid, divertor, cryostat) and field-line/label switches.
- Plasma colour and intensity are mapped from simulated core temperature and fusion
  power; the coil highlight follows selection. Field lines and glow are explicitly
  labelled as schematic, not MHD output.
- WebGL failures are caught by an error boundary; the rest of the console keeps working.

### Live data
- 30 channels sampled every 0.5 simulated seconds into a 4 800-sample ring buffer.
- Charts refresh at 4 Hz, the engine publishes at 12 Hz, the 3D scene reads state per
  frame — the page tree is never re-rendered at 60 Hz.
- Time windows 30 s / 1 min / 5 min, hold/freeze, hover crosshair with units,
  per-chart CSV export, threshold lines, dual axes, and a temperature-vs-fusion
  correlation scatter with Pearson *r*.
- Ten stacked diagnostics charts plus the correlation plot on the DIAGNOSTICS page.

### Controls and causality
Eight validated setpoints, applied immediately:
NBI / ECH / ICH power, TF coil current, plasma current request, fuelling density,
coolant flow, coolant inlet temperature.

Each propagates through the model chain, e.g.:
`NBI +15 MW → absorbed heating ↑ → dW/dt > 0 → T ↑ → ⟨σv⟩ ↑ → P_fusion ↑ → Q_plasma ↑
→ thermal power ↑ → coolant ΔT ↑ → gross MWe ↑ → net electric ↑ (plant loads also ↑)`.
Changing coolant flow changes loop ΔT, exchanger loading and the cold-leg temperature;
changing coil current slews the coil (1.4 s L/R lag), moves B_tor, field quality,
confinement and the stability index.

### Fault injection (8 faults)
Heating droop · magnetic disturbance · coil overheat · coolant loss · vacuum leak ·
sensor bias · sensor dropout · sensor latency.

Each has severity control (5–100 %), trigger timestamp, effect description, simulated
diagnosis, affected parameters, and recovery steps. Active faults show live
consequences; injection can be suspended (consequences removed, records retained);
alarms are generated by rules running on the simulation state, never decorative.

### Simulation Lab
- All controls plus model parameters: time scale, H98 factor, disturbance level,
  measurement noise, heat recovery, run duration, PRNG seed, initial conditions.
- Baseline / High Heating / Cooling Stress / Magnetic Disturbance / Custom scenarios.
- **WHAT-IF analysis**: two isolated headless engine runs, a 15-metric comparison
  table, overlaid time series and integrated energy balances.
- Presets saved to browser storage (create, duplicate, load, delete).
- Every parameter change is timestamped in the event log with old → new values.

### History, recording and playback
- Capture the live buffer or load a session saved in `localStorage`
  (survives a page refresh, compacted to fit the quota, oldest evicted first).
- Range selection, playhead scrubbing, replay at 1×/4×/8×/20×, per-sample read-out.
- Compare dataset A vs dataset B (integrated thermal/net-electric energy, peaks, Q, stability).
- Export the selected range as CSV or JSON; export the event log as CSV.
- Playback is read-only and cannot perturb the running simulation.

## 3. Architecture

```
src/
  simulation/                 # pure TypeScript — no React, no DOM
    FusionSimulationEngine.ts # fixed-step integrator, fault effects, snapshots, headless runs
    PlasmaModel.ts            # reactivity, fusion power, energy balance, IPB98(y,2), beta, limits
    MagneticFieldModel.ts     # B_tor / B_pol, coil slew, cold-mass thermal balance, field quality
    HeatingModel.ts           # delivery chain, wall-plug efficiency, waste heat
    ThermalModel.ts           # coolant loop, heat exchanger, vacuum, equipment states
    PowerBalanceModel.ts      # explicit site boundary, Q_plasma vs Q_engineering
    StabilityModel.ts         # transparent penalty scoring
    AlarmEngine.ts            # rule set with dedupe + cooldown, raise/clear transitions
    faults.ts                 # fault catalogue + diagnosis/recovery guidance
    controlSpecs.ts           # ranges, units, defaults, scenario definitions
    scenarios.ts              # headless runs + comparison table
    tokamakGeometry.ts        # shared 2D/3D coil geometry
  store/
    simulationStore.ts        # Zustand store + runtime loop + actions
    historyBuffer.ts          # ring buffer + localStorage persistence
  components/
    layout/ charts/ reactor/ panels/ controls/ diagnostics/ ui/
  pages/                      # one module per console page (lazy-loaded)
  utils/                      # units, validation, export, math, power
  tests/                      # models / engine / store suites
docs/screenshots/             # screenshots captured from the running console
scripts/audit.mjs             # headless interaction + layout audit
.github/workflows/ci.yml      # typecheck + tests + build on Node 20 and 22
```

**Single source of truth.** The engine owns all state. The store publishes immutable
snapshots (`SimFrame`) at 12 Hz. Charts read the ring buffer, the 3D scene reads live
state with `useFrame`, and every component displays values it received from one of
those two paths. No component invents or perturbs a number.

**Data flow**

```
operator input → validate → engine.setControl/setConfig
      → fixed-step physics (50 ms simulated)
      → derived metrics & alarms
      → snapshot (12 Hz) ──┬─→ KPI tiles, tables, status bar
                           └─→ 3D scene
      → history sample (0.5 s simulated) → ring buffer → charts (4 Hz)
      → events → event log → export / local session
```

## 4. Physics models

All equations are shown verbatim inside the app (REACTOR, MAGNETIC, COOLING, POWER and
SIMULATION pages). They are deliberately simple, documented and bounded.

| Model | Equation | Notes |
| --- | --- | --- |
| D-T reactivity | `⟨σv⟩ = 3.68e-12 · T^(-2/3) · exp(-19.94 / T^(1/3)) cm³/s` | NRL Plasma Formulary fit, T in keV, clamped 0.2–100 keV |
| Fusion power | `P_fus = (n_e/2)² · ⟨σv⟩ · 17.59 MeV · V` | 50:50 D-T, `n_D = n_T = n_e/2` |
| Stored energy | `W = 3 n T V` | electrons + ions, single temperature |
| Energy balance | `dW/dt = P_aux,abs + P_α − W/τ_E − P_rad` | explicit Euler at 50 ms |
| Alpha heating | `P_α = 0.2 · P_fus` | |
| Bremsstrahlung | `P_rad = 5.35e-37 · Z_eff · n² · √T · V` | `Z_eff = 1.5` |
| Confinement | `τ_E = 0.0562 · H · Ip^0.93 · Bt^0.15 · P^-0.69 · n_19^0.41 · M^0.19 · R^1.97 · ε^0.58 · κ^0.78` | IPB98(y,2); R = 6.2 m, a = 2.0 m, κ = 1.7, M = 2.5 |
| Toroidal field | `B_tor = µ₀ · N_tf · I_coil / (2π R₀)`, `N_tf = 2 412` turns | 5.29 T at 68 kA |
| Poloidal field | `B_pol = µ₀ · Ip / (2π a)` | edge value |
| Coil current | `dI/dt = (I_set − I) / τ_LR`, τ_LR = 1.4 s | first-order slew |
| Coil thermal | `C dT/dt = I²R + Q_AC + Q_fault − h·cryo·(T − 4.3 K)` | C = 9 kJ/K, h = 260 W/K (compressed for the demo) |
| Beta | `β_t = 2µ₀p/Bt²`, `β_N = β_t·a·Bt/Ip` | |
| Density limit | `n_GW = Ip / (π a²)`, `f_GW = n / n_GW` | |
| Safety factor | `q95 ≈ (2π a² Bt / (µ₀ R Ip)) · (1+κ²)/2 · 1.17` | |
| Coolant loop | `ΔT = Q_thermal / (ṁ · c_p)`, c_p = 4 180 J/kg·K | lagged with 6 s / 2.5 s time constants |
| Heat exchanger | `Q_cap = 700 MW · (ṁ/12 000)^0.8` | overload raises the cold-leg temperature |
| Rankine cycle | `η = 0.33 · derate(|T_mean − 255 °C|)`, ±30 K plateau | capped at 0.35 |
| Plant loads | heating wall-plug + magnets (∝B²) + cryo + pumps (∝ṁ³) + vacuum + controls | |
| Vacuum | `p → (p_base + leak) / pumping`, τ = 2.5 s | |

### Energy gain: two different boundaries

```
Q_plasma      = P_fusion / P_aux,absorbed                 (plasma boundary)
P_thermal     = P_fusion + P_aux + recovered waste heat    (MWth)
P_gross       = η_Rankine · P_thermal                      (MWe)
P_aux,plant   = heating grid + magnets + cryo + pumps + vacuum + controls
P_net         = P_gross − P_aux,plant                      (< 0 = importing)
Q_engineering = P_net / P_aux,plant                        (site boundary)
```

`Q_plasma` is **never** used as a plant-efficiency figure. At the reference operating
point the model gives roughly `Q_plasma ≈ 4.4` with `Q_engineering ≈ −0.46`, because
neutral-beam wall-plug efficiency is 35 % and the plant therefore recirculates more
electricity than it generates. Any zero (or invalid) denominator yields `null`,
rendered as **N/A** — never `Infinity`.

### Calibration and honesty notes

- Geometry and reference values are *generic ITER-like DEMO* figures chosen to give
  plausible orders of magnitude; they are not any machine's design parameters.
- The default H98 factor is **1.2** (enhanced-confinement assumption) and is adjustable
  0.6–1.8 in the Simulation Lab; it is the single largest lever on the operating point.
- Cold-mass heat capacity/conductance, density response and coil slew are **compressed
  in time** so transients are observable in an interactive session.
- No profile, transport, MHD, current-drive, tritium or neutron-transport physics is modelled.
- Startup uses the configured initial conditions rather than a ramp-up sequence.

## 6. Data, persistence and export

- **CSV**: full column set with unit-suffixed headers, a `#` metadata preamble including
  the `SIMULATED / DEMO DATA` classification. Available per chart, for the whole
  history, for a playback range, and for the event log.
- **JSON**: session export with disclaimer, controls, config, samples, events, alarms.
- **localStorage**: `fusionplant.sessions.v2` (max 2 sessions, ≤1 400 downsampled
  samples each, oldest evicted on quota errors) and `fusionplant.presets.v1` (≤20 presets).
  Quota failures are reported in the UI instead of throwing.
- Nothing leaves the browser: no telemetry, no analytics, no network requests.

## 7. Security

This project holds no credentials and makes no network calls.

- **No secrets in the repository.** There is no backend, no API client and no `.env`
  value in use. `import.meta.env.DEV` is the only environment read in the codebase.
- **`.env.example`** documents that no variables are required and explains why a
  `VITE_`-prefixed variable is *always public* (Vite inlines it into the client bundle).
- **`.gitignore`** covers `node_modules/`, build output, caches, logs, editor files,
  `.env*` (with `!.env.example`), key material (`*.pem`, `*.key`, `*.p12`, `id_rsa*`, …)
  and local audit artefacts (`.smoke/`).
- **Audit of the working tree, build output and git history** was performed before
  release: pattern scan for known credential formats (`sk-…`, `ghp_…`, `AKIA…`,
  `xox…`, PEM private keys, JWTs), a generic secret-keyword scan, a personal-path
  scan (`/Users/…`), plus a `gitleaks` scan of the full history. Results are recorded
  in the release report; no credential was found.
- If you ever add a secret-bearing feature (for example an LLM call), **do not** call
  the provider from the browser. Add a server-side proxy and keep the key out of the
  bundle. Any secret shipped to a browser is public.

If you find a leaked credential in this repository, please contact the maintainer
privately rather than opening a public issue.

## 8. Known limitations / not implemented

These are deliberate scope cuts, not hidden gaps:

1. **0-D physics only.** No radial profiles, transport solver, MHD stability, SOL/divertor
   plasma or current-drive physics. The "stability index" is a weighted penalty score.
2. **No real CAD.** The 3D device is procedurally generated from a handful of parameters;
   it is not engineering geometry and is not dimensionally certified.
3. **No tritium cycle**, breeding blanket, neutronics, activation or maintenance model.
4. **Startup is instantaneous** to the configured initial conditions (no plasma ramp-up,
   coil charge sequence or interlock logic).
5. **SCRAM is a latch**, not a sequence: the plant freezes at the trip point; RESET
   re-initialises rather than simulating a controlled shutdown.
6. **Time constants are compressed** where needed for interactivity (documented above).
7. **Single-run playback only** — no multi-track timeline editor; comparison is A vs B.
8. **No i18n framework**; the console UI is English (matching the industrial idiom) with
   a Chinese overview in this README.
9. Charts render the retained in-memory window (≤4 800 samples ≈ 40 min of simulated time
   at 0.5 s sampling); older data is not archived.
10. The audit script is a development tool: it requires Chrome and a running dev server,
    so it is intentionally not part of CI.

## 9. Roadmap

- **Physics**: 1.5-D transport (two-point model / profile parameterisation), proper
  current-drive and bootstrap fractions, divertor heat-flux proxy, disruption predictor
  trained on simulation data.
- **Operations**: scripted pulse sequences (ramp-up / flat-top / ramp-down), interlock
  matrix, role-based control permissions, maintenance-mode equipment availability.
- **Data**: IndexedDB archive with longer retention, run catalogue with search/tagging,
  and delta comparison between any two runs.
- **Visualisation**: shader-driven plasma with temperature-dependent emission, flux-surface
  overlays, interactive 2D equilibrium contour from a Grad-Shafranov surrogate.
- **Validation**: property-based tests over the engine's numeric domain, per-model
  benchmark fixtures, and a visual-regression harness for the console layout.
- **Platform**: optional Web Worker execution of the engine, plus a headless CLI runner
  for batch experiments.

## 13. Design language

Dark industrial control-room palette: near-black blue surfaces, cyan for nominal
telemetry, violet/magenta for plasma and field visualisation, amber for warnings, red
for faults. Hairline grid textures, corner ticks, monospaced tabular numbers, dense but
grouped layout, 9–11 px label scale, 16:9-first with a tablet-safe stacking layout.
No game-style UI, no decorative fake telemetry.
